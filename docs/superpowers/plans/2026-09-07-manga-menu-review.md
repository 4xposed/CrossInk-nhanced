## Issues

### Critical

### Important

**R1 — A deferred render can leave auto-turn permanently waiting for itself.** `src/activities/reader/MangaReaderActivity.cpp:874` requires `!pendingRender` before an automatic turn, but the active-auto branch returns at `:881`, before the only clearing/service path at `:976`. A concrete sequence is: request a manual refresh while prefetch is running; `render()` returns with `pendingRender = true` (`:1272`); queue the reader menu before the worker finishes; when it drains, the menu takes priority at `:844` and returns through its modal path. Neither a successful menu render nor rate selection (`:434`) clears the old flag. Selecting a rate then renders the page but leaves `pendingRender` set forever. The automatic clock never sees idle and never advances; `preventAutoSleep()` remains true. Service deferred rendering before the automatic branch, or retire the pending flag when its render request is successfully fulfilled. Add a deterministic worker-drain → deferred render → menu → rate-selection regression, asserting a turn eventually occurs and only one deadline is re-armed. On hardware, reproduce with refresh/menu entry during slow prefetch, select 12/min, and verify it advances after the completed frame without requiring cancellation.

**R2 — Ordinary prefetch warming silently drops configured lookup.** `src/activities/reader/MangaReaderActivity.cpp:530` rejects the shortcut whenever `prefetch && !prefetch->idle()`, before storing an intent or canceling work. The worker's `idle()` is false for ordinary Posted/Running work and an unconsumed Finished result, not just foreground cancellation drain (`lib/MangaPanel/MangaPrefetchState.h:10`, `:17`, `:23`). Thus short-power/chord lookup pressed while speculative warming is active returns false and disappears, while menu/Confirm lookup uses the retained intent and drain flow (`MangaReaderActivity.cpp:243`, `:920`). This fails the requested same-current-view shortcut behavior and rejects more than the specified modal/lock/suspend/foreground-drain states. Distinguish an existing foreground drain from normal warming; for normal warming, retain the lookup and request cancellation, then launch once idle. The simulator currently conceals this failure by retrying the shortcut and forcing manual refresh until accepted (`src/simulator/SimulatorSmokeTest.cpp:1657`), behavior the physical one-shot button release cannot perform. Replace/add a one-shot test during ordinary Running/Finished prefetch and a separate rejection test during an already owned foreground drain. On C3/S3, press the configured shortcut immediately after a page renders while the next crop is warming; it should launch once and return to the same page/panel.

### New breakage introduced by correction round 1
