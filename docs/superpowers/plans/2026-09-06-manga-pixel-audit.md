# Task 7 manga pixel pipeline architecture audit

## Scope and reference

This is a read-only design audit for the Task 6 manga reader now in the CrossInk worktree. It compares the current decoder/cache/display seams with `/Users/daniel/code/matcha-reader` at pinned SHA `61ca61ba86e3c5709a24d1b9c4f3cf2d41488012`. It does not propose importing Matcha's prefetch task or changing `freeink-sdk`; the firmware has about 11 KB of OTA headroom and the ESP32-C3 must retain one 48 KB framebuffer.

## Findings

### Geometry must be computed once and reused verbatim

`MangaReaderActivity::drawImageLocked()` currently probes the source, temporarily rotates wide panels, derives bezel-safe bounds, scales, and centers at `src/activities/reader/MangaReaderActivity.cpp:451-498`. It then gives JPEG/PNG the exact derived size (`useExactDimensions = true`) at `src/activities/reader/MangaReaderActivity.cpp:510-518`; BMP uses the same rectangle at `src/activities/reader/MangaReaderActivity.cpp:500-507`. This is the right ownership boundary, but the values are local and therefore unavailable to cache validation and the two future grayscale plane replays.

Introduce a small value type beside the activity, for example `MangaImageGeometry { savedOrientation, drawOrientation, x, y, width, height }`, and pure helpers that accept source dimensions, base orientation, runtime screen dimensions, bezel-safe TRBL, panel/overview state, and `rotatePanels`. Have one helper compute the rectangle and one short scoped operation apply/restore the orientation. Both overview and panel rendering should consume this exact object for BW decode/cache replay, LSB replay, and MSB replay. Use integer cross-products for aspect decisions and fixed rounding in one place; do not recompute dimensions from margins in separate passes. Matcha documents a real 480x682 versus 480x684 cache miss caused by duplicate rounding at `matcha-reader/src/activities/reader/MangaReaderActivity.cpp:610-638`.

Keep CrossInk's behavior where BMP never upscales (`src/activities/reader/MangaReaderActivity.cpp:491-496`) unless a separate product decision changes it. JPEG/PNG currently may upscale because exact dimensions bypass each decoder's normal no-upscale branch (`lib/Epub/Epub/converters/JpegToFramebufferConverter.cpp:438-450`, `lib/Epub/Epub/converters/PngToFramebufferConverter.cpp:367-380`). Geometry tests should lock this format distinction.

### The writer is reusable; the current cache format and reader are not

`RenderConfig::cachePath` already exposes the writer hook at `lib/Epub/Epub/converters/ImageToFramebufferDecoder.h:15-23`. JPEG initializes a bounded band and writes during its normal callback at `lib/Epub/Epub/converters/JpegToFramebufferConverter.cpp:494-504`, while PNG does the same at `lib/Epub/Epub/converters/PngToFramebufferConverter.cpp:429-441`. The callbacks write the identical quantized 2-bit value to the framebuffer and cache (`lib/Epub/Epub/converters/JpegToFramebufferConverter.cpp:194-215`, `lib/Epub/Epub/converters/PngToFramebufferConverter.cpp:246-286`), which is the required fresh-versus-cached pixel parity seam. Working memory is capped at 24 KB plus one zero row (`lib/Epub/Epub/converters/PixelCache.h:58-90`), rather than a second full image/framebuffer.

Do not expose `PixelCache` itself as the public API. It is a writer struct with public mutable fields, writes a four-byte native-endian `{uint16 width,uint16 height}` header directly to the final path, and has no magic, version, source identity, payload length equality, or checksum (`lib/Epub/Epub/converters/PixelCache.h:28-54`, `lib/Epub/Epub/converters/PixelCache.h:99-116`). The only current reader is private inside `ImageBlock.cpp`; it accepts files larger than the expected payload and tolerates dimensions by one pixel (`lib/Epub/Epub/blocks/ImageBlock.cpp:75-90`). That is unsafe for a new durable manga cache and cannot distinguish a stale file produced by another geometry/dither policy.

Extract a compact `PixelCacheIO` reader/writer facade into `lib/Epub/Epub/converters/PixelCache.{h,cpp}` while leaving decoder row emission intact. Recommended v1 header fields, encoded explicitly little-endian, are: 32-bit magic, 8-bit version, 8-bit pixel format (`2-bit MSB-first, levels 0..3`), 16-bit flags/reserved, 16-bit width and height, 32-bit source byte size, 32-bit render-policy signature, and 32-bit payload checksum. The policy signature must cover dimensions, dithering algorithm/version, and any tone/alpha policy that changes packed pixels. Exact file length must equal `headerBytes + ceil(width/4)*height`. A source-size identity is available from the already-open source probe (`HalFile::fileSize()` is exposed at `lib/hal/HalStorage.h:109`); include the stable manga asset identity in the cache filename (page or page+panel and a format/version prefix). If source replacement with equal byte size must be detected, add a bounded streaming source checksum during decode rather than relying on unavailable mtime APIs.

Write `*.tmp`, close it, validate/promote it, and only then replace the final cache. The present writer removes the final path on abort (`lib/Epub/Epub/converters/PixelCache.h:142-177`), so interruption can destroy a previously valid cache and a reset can leave a plausible partial file. CrossInk already has a recoverable temp/backup promotion pattern at `src/activities/reader/PageWordScanCache.cpp:307-333`; reuse its behavior without generalizing that feature.

The reader should own one `HalFile`, read and validate the header once, expose dimensions/identity, rewind to the payload before each render, and close explicitly. Stream roughly 4 KB of rows with a one-row allocation fallback, as the current `ImageBlock` reader does at `lib/Epub/Epub/blocks/ImageBlock.cpp:243-314`. Retaining a full 96 KB PXC is PSRAM-only in EPUB (`lib/Epub/Epub/blocks/ImageBlock.cpp:101-109`, `lib/Epub/Epub/blocks/ImageBlock.cpp:188-216`) and should not be added to manga; a single shared streamed reader keeps C3 behavior deterministic. Matcha's reusable reader is the useful small idea (`matcha-reader/lib/Epub/Epub/converters/PixelCache.h:18-64`), but its four-byte unversioned format should not be copied.

### File lifetime and failure rules

Task 6 explicitly closes the BMP/source probe before reopening it for drawing (`src/activities/reader/MangaReaderActivity.cpp:456-478`, `src/activities/reader/MangaReaderActivity.cpp:500-507`). Preserve this rule. For JPEG/PNG, open and validate the cache first. On a warm hit, keep that one cache handle through BW, LSB, and MSB, seeking back to the payload for each pass. On a miss or failed read, close the cache before calling the decoder; after a successful decode/finalize, reopen the cache for plane replay. No decoder or source `HalFile` should outlive the render call, consistent with `src/activities/reader/MangaReaderActivity.h:13-14`.

A cache creation failure must not turn a successful BW decode into a page error. It should log, leave no temp file, and degrade to decoder replay for the gray planes. A plane replay/decode failure should skip grayscale and keep the already displayed BW page. Never clear the framebuffer after the BW wave unless the BW backup has succeeded.

### Grayscale sequence and mandatory BW backup

Use the existing renderer sequence, not a new display API. The reusable contract is demonstrated by `ReaderUtils::renderAntiAliased()` at `src/activities/reader/ReaderUtils.h:234-259`: store BW, clear to `0x00`, render/copy LSB, clear, render/copy MSB, display gray, restore BW, and return render mode to `BW`. The renderer owns the hardware-facing calls at `lib/GfxRenderer/GfxRenderer.h:314-335` and delegates to the pinned SDK at `lib/GfxRenderer/GfxRenderer.cpp:3009-3047`.

For manga, first compose the BW image, display it with the reader refresh cadence using `displayGrayscaleBase(FAST_REFRESH)` when gray planes will follow, then build both planes from the same open cache and geometry. If `storeBwBuffer()` fails, log and stop before either clear; EPUB already enforces this at `src/activities/reader/EpubReaderActivity.cpp:6466-6495`. Matcha's full-page code calls `storeBwBuffer()` without checking at `matcha-reader/src/activities/reader/MangaReaderActivity.cpp:802-824`; do not copy that bug. Its panel path has the correct degradation at `matcha-reader/src/activities/reader/MangaReaderActivity.cpp:1003-1032`.

After `displayGrayBuffer()`, restore the BW framebuffer because future diffs assume it contains the displayed base. `restoreBwBuffer()` frees the backup chunks, so the temporary memory is bounded and no second resident framebuffer is introduced. If tiled grayscale is later needed for lower-heap states, use the existing strip target APIs (`lib/GfxRenderer/GfxRenderer.h:230-235`, `lib/GfxRenderer/GfxRenderer.h:331-332`) and the orientation-aware cache clipping already implemented for EPUB (`lib/Epub/Epub/blocks/ImageBlock.cpp:46-73`); that is a follow-up optimization, not required for Task 7's smallest integration.

### Task 8 cancellation seam

Do not add a worker or prefetch task in Task 7. Make the cache API ready for cancellation with a tiny C-style callback in `RenderConfig`: `bool (*shouldCancel)(const void*)` plus `const void* cancelContext`, default null. Poll it once per JPEG MCU callback immediately beside `yieldDuringDecode()` (`lib/Epub/Epub/converters/JpegToFramebufferConverter.cpp:124-129`) and once per PNG scanline (`lib/Epub/Epub/converters/PngToFramebufferConverter.cpp:208-213`). On cancellation, mark the decoder context explicitly, abort/remove the temp cache, close the source, and return false. Explicit state is necessary because JPEGDEC may report success after a callback asks it to stop; Matcha calls this out in `matcha-reader/lib/Epub/Epub/converters/ImageToFramebufferDecoder.h:54-62` and implements the probes in its JPEG callback at lines 141-153 and PNG callback at lines 246-250. Keep framebuffer writes enabled for Task 7; a future `cacheOnly` flag belongs to Task 8 when a worker actually exists.

## Recommended smallest integration

1. Add a pure shared manga geometry value/helper and make the existing BW draw consume it. Preserve the current format-specific upscale behavior and restore orientation on every exit path.
2. Turn `PixelCache` into a versioned, atomic streaming writer plus a public streaming reader. Keep the existing JPEG/PNG callback row hooks and 24 KB ceiling. Update EPUB `ImageBlock` to use the facade so there is one cache format and validation policy.
3. Name manga caches inside the existing per-book directory (`manga::cachePath()` at `lib/MangaPanel/MangaCover.cpp:134-142`) with distinct overview/panel identities and the format version; pass the path through `RenderConfig` only for JPEG/PNG. BMP stays on `GfxRenderer::drawBitmap()` and remains BW-only for this task (`src/activities/reader/MangaReaderActivity.cpp:500-518`).
4. On a cache hit, hold one reader open for BW/LSB/MSB. On a miss, close it, decode once while streaming the temp cache, then reopen for both gray planes. Display BW first and require `storeBwBuffer()` before plane construction.
5. Document the new PXC header/version in `docs/file-formats.md` when implemented. Cache version/policy mismatches are ordinary misses: close, remove or overwrite atomically, and regenerate.

## Verification targets for the implementation task

Host tests should cover exact geometry parity across all four orientations, wide-panel auto-rotation, bezel-safe bounds, no-upscale BMP behavior, and identical rectangles for fresh and cached paths. Pixel-cache tests should cover header byte order/version, exact length, truncated/oversized payload rejection, wrong source identity/policy rejection, checksum failure, temp cleanup, promotion rollback, and byte-identical BW/LSB/MSB output between a fresh decoder stream and cache replay.

On an Xteink X3/X4, test cold and warm overview and panel views for JPEG and PNG, then a 1-bit BMP. Expected behavior is one cold JPEG/PNG decode, sequential cache reads for gray planes and warm revisits, no second framebuffer allocation, a usable BW image if backup/cache allocation fails, and unchanged BMP BW rendering. Interrupt a cold decode with Back/power after Task 8 adds cancellation; no final cache should appear and reopening the page should decode normally. Clear `/.crosspoint/manga_<folder-crc>/` before cold-path checks because existing files can mask writer and freshness bugs.
