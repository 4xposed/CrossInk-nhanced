# Manga full-handoff completion gap audit

2026-09-06. Read-only source audit, plus this report. No builds, code edits, commits or hardware verification. Scope: remaining Tasks 1–7/library requirements that Task 8 prefetch and Task 9 lookup do not automatically complete. CrossInk CodeGraph was consulted first; pinned Matcha source remains the reference described in the handoff.

## Must fix before claiming the complete handoff

### Cover cancellation and PNG allocation failure

`lib/MangaPanel/MangaCover.h:11` exposes no cancellation callback. Generation performs a full source CRC (`MangaCover.cpp:58`, `:179`) and synchronous conversion (`:209`) before publication. Home and grid call it directly (`HomeActivity.cpp:721`, `:798`; `RecentBooksGridActivity.cpp:298`); SleepCoverAssets also calls it (`:52`, `:86`). Task 8's ImageToFramebufferDecoder worker does not cover these JpegToBmpConverter/PngToBmpConverter paths.

Minimum: optional lightweight cancellation callback/context propagated through cover CRC, BMP row loops and both actual ToBmp converter loops/callbacks; caller lifecycle/input must be able to set cancellation while conversion runs. Merely adding an unused argument is insufficient. If the caller currently blocks its input loop in generation, move only generation to a bounded owned worker or resumable work flow, with renderer drawing retained on its owner task. Close and discard temporary output on cancellation and avoid retry storms; retain a placeholder/old validated cover. Sleep generation needs a defined cancellation/shutdown policy as well. Do not allocate another framebuffer.

There is a concrete reachable C3 allocation bug in the PNG cover converter: `MangaCover.cpp:212` calls `PngToBmpConverter.cpp:914`, whose internal one-bit path performs bare `new Atkinson1BitDitherer(outWidth)` (`:697`); scaled covers also allocate `new uint32_t[outWidth]` and `new uint16_t[outWidth]` (`:713`). On no-exception ESP32 builds these can abort. Convert the reachable allocations and ditherer backing storage to checked fallible ownership, log and cleanly return failure. Audit complete constructors, not just the outer pointer: `lib/GfxRenderer/BitmapHelpers.h:27` allocates three error rows with bare `new[]`. Existing cover tests compile stub JPEG/PNG converters (`test/manga_cover/CMakeLists.txt:1`), so their passes do not verify this path.

**Do not fix an imaginary BMP-default bug:** `MangaCover.cpp:91` uses `Bitmap(source)`, but `lib/GfxRenderer/Bitmap.h:67` defaults `dithering=false`; the bare-new dithering branch in `Bitmap.cpp:169` is not reached by that call. BMP cover scratch already uses `makeUniqueNoThrow` (`MangaCover.cpp:101`). An explicit `false` could improve readability but is not a behavior fix.

### Language attribution

The handoff explicitly includes language attribution. `MangaBook.h:33` already exposes the optional meta.bin language; no format change is needed. Neither `BookReadingStats.h:9` nor `GlobalReadingStats.h:9` stores a language dimension, and manga `commitReadingStats()` (`MangaReaderActivity.cpp:439`) only adds total time/calendar buckets. Dictionary routing from language is separate and cannot satisfy reading-time attribution.

Pinned Matcha calls `ReaderUtils::flushReadingStats(..., book->getLanguage().c_str())` on periodic flush and exit (`../matcha-reader/src/activities/reader/MangaReaderActivity.cpp:159`, `:412`). Its `ReadingStatsStore.h:13` and `:26` hold book language and language/day totals, including an unknown bucket. Avoid importing its entire stats/UI system. Minimum meaningful CrossInk integration: extend existing stats persistence with bounded language attribution, feeding exactly the same committed reading interval into total and language accounting, preserve unknown language and normalize tags consistently. A language string alone does not attribute durations if language metadata changes later. If day-level parity is claimed, preserve language/day attribution too; otherwise explicitly record the remaining gap. Version new binary layouts and keep old readers/migration defaults, stats clear, synced aggregation and completion/cache preservation consistent. Reuse the existing timer so menus/input lock/child lookup do not double count. Add round-trip/backward-read and mixed/unknown-language accounting tests.

### Supported external folder operations

Do not claim that folder moves are unavailable everywhere. On-device directory menus expose delete/cache/stats/completed actions but no move/rename (`FileBrowserActivity.cpp:472`). HTTP rename and move explicitly reject folders (`CrossPointWebServer.cpp:1080`, `:1146`), and moving completed books to `/Read` is EPUB-only (`BookActions.cpp:254`). Those surfaces require no new manga move UI merely for parity.

However, WebDAV MOVE accepts an open directory and renames it (`WebDAVHandler.cpp:543`–`:555`), and USB serial RENAME calls `Storage.rename` without a file-only check (`UsbSerialFileTransfer.cpp:569`–`:599`). Neither migrates manga progress/bookmarks/stats/recents/resume paths. USB cache clearing after rename cannot identify the removed source as a manga folder. Renaming a parent folder also changes every contained manga identity. Handoff language requires this actual surface to be handled, not hidden by the on-device limitation.

Minimum: a shared bounded pre-operation snapshot of affected manga book paths; after successful transport move, migrate durable path-keyed records and recent/resume references to the derived destination, while treating pixel/thumbnail caches as disposable. Preserve state on move failure; detect destination-state collisions and never overwrite unrelated state silently. Include ancestor moves and recovery from partial metadata migration. If this cannot be implemented in the current change, explicitly leave the acceptance requirement incomplete; documentation that state is lost is not a feature-completion claim. Raw SD/USB mass-storage changes occur outside firmware mediation and need a documented path-identity limitation, rather than pretending firmware can observe arbitrary offline renames.

HTTP recursive folder deletion directly uses `Storage.removeDir` (`CrossPointWebServer.cpp:1259`) without the device browser's manga metadata snapshot/cleanup. Reuse the same bounded pre-delete bookkeeping for this route if claiming consistent supported deletion. WebDAV only permits empty-directory deletion (`WebDAVHandler.cpp:421`), so deleting a normal nonempty manga directory there is already rejected; do not broaden that API as incidental cleanup. USB REMOVE is also recursive (`UsbSerialFileTransfer.cpp:265`, `:561`) and only calls generic cache clearing for removed child files (`:278`); apply the same pre-delete manga metadata bookkeeping there.

## Already covered in the inspected implementation

- First-page cover selection does not substitute panel crops (`MangaCover.cpp:171`); JPEG/PNG/BMP dispatch, size bounds, source identity validation, complete BMP structural validation and temporary-pair cleanup exist (`:159`–`:236`). No second framebuffer is allocated by this wrapper. These are source findings, not physical image certification.
- On-device manga directory actions reuse BookActions (`FileBrowserActivity.cpp:477`); completion and per-book stats integrate with existing stores (`BookActions.cpp:177`, `:182`). Manga intentionally does not inherit EPUB-only render/reset/move-to-Read controls.
- On-device recursive delete snapshots manga metadata before removing book markers (`FileBrowserActivity.cpp:436`; `BookDeletionSnapshot.h:16` gives fixed arena/entry bounds); `BookActions.cpp:109` removes manga cache, durable progress and bookmarks. This makes the HTTP bypass above identifiable rather than requiring a new deletion architecture.
- User cache clear uses `clearBookCachePreservingUserState`: manga preserves stats within its cache; progress lives outside that cache and bookmarks use their existing store (`src/util/BookCacheUtils.cpp`, manga branch of that function). Do not delete these durable records to simplify cache invalidation.
- The implementation ledger already acknowledges missing per-language stats and external move migration (`2026-09-05-manga-port-implementation.md:139`). These remain acceptance gaps, not newly discovered regressions in otherwise claimed-complete work.
