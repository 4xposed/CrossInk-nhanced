# Manga menu completion audit

2026-09-06. Read-only implementation audit plus this report. CrossInk CodeGraph was consulted before targeted source reads. The behavioral reference is Matcha `61ca61ba86e3c5709a24d1b9c4f3cf2d41488012`; the approved inventory is the [reader audit](2026-09-05-manga-reader-audit.md) and the [port design](../specs/2026-09-05-manga-port-design.md). No build or hardware test was performed.

## Finding

The current manga menu is not feature-complete. `MangaReaderActivity::showMenuLocked()` has eleven rows: chapter, percent, bookmarks, toggle bookmark, Panels Only, panel rotation, screen orientation, Home, lookup, stored translation and lookup history (`src/activities/reader/MangaReaderActivity.cpp:240-253`). The first eight cover the reader navigation/state actions already approved, and the final three are the Task 9b unified-dictionary adaptation. Five pinned user-visible commands remain absent: filtered reader settings, auto page turn, screenshot, delete cache and OCR QR. The pinned page/panel status overlays are also absent from the current manga renderer.

Global shortcuts do not close these gaps. The touchscreen settings escape hatch calls `openReaderSettingsMenu()`, which currently opens the same manga menu (`MangaReaderActivity.cpp:231-253`; `ActivityManager.cpp:651-661`). Screenshot is available only when the user has assigned a power/chord shortcut (`src/main.cpp:533-564`, `:699-709`). Cache deletion exists in Home, Recent and browser action menus through `BookActions`, but leaving the book to find that action is not the pinned reader-menu behavior. Home/global orientation gestures likewise do not make required menu rows optional. The menu must expose all five on button-only and touch profiles through the applicable menu-entry route.

The root handoff clarifies one intentional CrossInk adaptation: Confirm in panel mode opens current-panel lookup directly. Current code still routes every Confirm release to the menu (`MangaReaderActivity.cpp:585-588`); Task 9b owns that correction and the pending/coalesced prefetch-drain tests. Preserve direct panel Confirm when completing this audit. Open the menu in panel mode through the touch menu gesture or global reader-settings/menu escape path, or return to overview before button Confirm; menu parity does not require replacing the direct-lookup binding.

## Smallest bounded implementation

Keep `MangaReaderActivity` as the policy owner and retain its current `OptionPopup`; it already serializes menu input with `RenderLock` and supports both mapped buttons and touch. Replace positional integer cases with a local enum and build a bounded row array so optional availability cannot shift handlers. Add the five commands without importing the EPUB menu's footnote, clipping, sync, reading-pace or ebook-render controls.

For filtered reader settings, add a transient manga settings view built from existing `SettingInfo` and Settings UI machinery. Do not launch the unfiltered Reader category: `buildReaderSettingsParentList()` includes font, page layout, publisher page numbers, EPUB images/styles, bionic reading, guide reading and indexing (`src/SettingsList.h:1135-1151`), most of which do not affect a raster manga page. Initially expose only settings already read by the manga path: reader touchscreen disable and the applicable mapped-input controls. Per-book Panels Only and panel rotation remain the existing manga menu rows, and orientation remains the existing orientation row. Do not list generic reader status-bar, font, margin, dark-mode, image, style, bionic, guide, dictionary or indexing controls unless the same change first wires their effect into manga and tests it. In particular, current manga rendering does not consume the generic reader status-bar layout, so that setting cannot be promised by the filter. This is a narrow filter over shared settings data and widgets, not a second settings system.

For screenshot, use `ScreenshotUtil::takeScreenshot(renderer)` only after the popup is dismissed and the manga image has been restored to the framebuffer, following EPUB's deferred `pendingScreenshot` pattern (`EpubReaderActivity.cpp:3629-3635`, `:5856-5858`). Implement `getScreenshotInfo()` for manga so menu and configured global shortcuts both produce a book/page/progress filename; `ScreenshotInfo` currently has no Manga value (`src/util/ScreenshotInfo.h:4-10`), but its non-EPUB filename branch already fits page-based books (`ScreenshotUtil.cpp:16-43`). Adding a Manga enum value is enough; no screenshot encoder fork is needed.

For delete cache, show the existing `ConfirmationActivity` wording, pause reading-time accounting while it is open, save pending progress and stats, stop/drain speculative work, close pixel/source handles, then call `clearBookCachePreservingUserState(folder)` (`src/util/BookCacheUtils.cpp:337-340`). On success show the existing cache-deleted feedback and return Home, matching the established EPUB flow (`EpubReaderActivity.cpp:3582-3619`). Failure must be logged and reported without claiming deletion. Do not call `BookActions::clearMangaMetadata()`: that function also deletes progress and bookmarks (`BookActions.cpp:109-118`), while pixel, cover and OCR scan outputs are disposable derived data.

## Auto page turn contract

Offer exactly Off, 1, 3, 6 and 12 turns per minute. Store the selected index only for the current reader session, as pinned Matcha does (`Matcha:src/activities/reader/MangaReaderActivity.cpp:43`, `:399-407`); do not silently inherit EPUB's per-book 5-120 second preference. The intervals are respectively disabled, 60, 20, 10 and 5 seconds, computed with integer arithmetic.

While active, the mode owns ordinary reader navigation. It cannot call the current manual `move(true)` unconditionally: manual forward navigation from an overview enters its first panel, while pinned automatic navigation calls `nextPage()` from overview and `nextPanel()` only from panel zoom (`Matcha:src/activities/reader/MangaReaderActivity.cpp:425-446`). Add a shared, directly testable automatic-forward helper: from panel view follow the normal next-panel transition, including crossing to the next page according to existing panel rules; from overview jump to the next physical page's overview, or its first real crop only when Panels Only/no-overview rules require that fallback. Reuse the same page-load, progress, completion and reading-stat bookkeeping as manual movement rather than duplicating it.

Confirm, Back, or the touch menu gesture cancels the mode and redraws its menu/status indication; Back must not also leave the reader on that release. Lifecycle exit, suspend, input lock and any child/menu launch must also clear it. Other page-turn inputs should be ignored while active, matching the pinned exclusive mode rather than creating two competing clocks.

Use wrap-safe `millis()` subtraction. Arm the first deadline when the user selects a rate. If foreground render, grayscale completion, source decode or prefetch cancellation is still busy when due, defer without accumulating turns and re-arm from the time the foreground becomes idle. After an automatic move, re-arm once from that move/render cycle; never replay missed intervals in a burst. Set `preventAutoSleep()` while active, as EPUB already does (`EpubReaderActivity.h:468`), because otherwise the device's global idle timer can sleep between the slower rates. Auto turns should use the same reading-stat transition as manual forward movement, while menu time and lock/suspend time stay excluded by the existing pause/resume timer.

The auto-turn menu row must show Off or the active 1/3/6/12 rate so reopening the menu exposes current session state. Pinned manga does not draw a per-second countdown on the page; do not invent one or force periodic e-ink refreshes. If CrossInk adds a compact active-mode label for parity with its EPUB affordance, draw it only during a normal reader redraw and cover it with the same opaque background as the other status text.

## Page and panel status overlays

Pinned Matcha always draws an opaque bottom-right page counter (`page/total`) for both monochrome and grayscale overviews (`Matcha:src/activities/reader/MangaReaderActivity.cpp:759-765`, `:793-800`). Panel view draws `panel/count  page/total` at bottom right and a translated Panels hint at bottom left (`:973-989`). Current CrossInk `MangaReaderActivity::render()` draws only the image, popup or load error (`src/activities/reader/MangaReaderActivity.cpp:963-989`), so these are remaining user-visible parity work; a generic configurable reader status bar is not their existing equivalent.

Render the two small opaque patches inside the oriented safe viewport, after image pixels are composed. For a 1-bit BMP/BW render, draw a white patch and black label into the sole BW framebuffer before display. Grayscale planes are delta masks rather than copies of BW pixels: zero leaves solid black/white base pixels alone, while set bits select gray transitions (`freeink-sdk/libs/display/FreeInkDisplay/src/driver/Uc8279X4Driver.cpp:320-329`). During each LSB/MSB pass, clear the status rectangles to zero instead of painting the BW patch bits; after grayscale, redraw white/black status into the restored BW framebuffer before `cleanupGrayscaleWithFrameBuffer()`. Deferred panel grayscale upgrades use the same mask clearing. This bounded helper needs no second framebuffer. Use runtime orientation/insets and measured text width so rotated screens and long translated Panels labels remain in bounds.

## Reader shortcut parity

Task 9b added lookup activities and menu commands, but `MangaReaderActivity` overrides neither `handleShortcutAction(uint8_t)` nor `handleShortcutAction(SHORT_PWRBTN)` and its loop does not inspect a Power lookup action (`MangaReaderActivity.h:39-48`; `MangaReaderActivity.cpp:535-677`). `ActivityManager` forwards configured reader shortcuts only through those virtuals (`ActivityManager.cpp:373-375`, `:694-697`). Consequently the configured short-power `WORD_LOOKUP` and Quick Actions/chord `LOOKUP_WORD` routes currently do nothing in manga, unlike pinned Matcha's short-power lookup (`Matcha:src/activities/reader/MangaReaderActivity.cpp:448-454`).

Wire both existing shortcut forms to the same current-view `openLookup()` entry point and availability/error behavior as the menu. Suppress a coincident screenshot chord release as the global input controller already requires, and reject the action while the popup, lock, suspend or foreground cancellation drain owns input. This is shortcut parity for the already-approved lookup feature; it does not add unrelated manga shortcuts.

## Offline OCR QR contract

Reuse `QrDisplayActivity` (`src/activities/reader/QrDisplayActivity.cpp:19-54`). Build its payload from the same immutable current-view OCR scope used by lookup: the selected panel's text blocks in panel mode, or all panels' text blocks in stored order for overview, separated by newlines. Never include stored translation and never invoke a network service. Missing or empty OCR should show `STR_MANGA_NO_OCR` and remain in the reader; malformed page metadata or allocation failure should log and show the existing load/memory error.

Bound payload construction before allocation. `QrUtils` currently truncates to 2,953 bytes on a UTF-8 boundary, but it first receives an already-built `std::string` and allocates its QR work buffer with throwing `std::make_unique` (`src/util/QrUtils.cpp:16-40`). Manga must not concatenate an unbounded page merely to have it truncated later. Add a shared QR payload builder capped at 2,953 UTF-8 bytes, append whole or safely truncated text blocks, and report truncation in logs. Make the QR work-buffer allocation fallible before treating this route as C3-safe. The rendered payload remains fully offline and exactly matches the bounded text assembled from the current OCR scope.

## Tests required

- A native menu-model test asserts the complete row/action mapping and verifies optional OCR/translation availability cannot shift screenshot, cache or Home actions. Simulator input opens the full menu from overview with button Confirm and from panel mode with the touch/global menu routes; a separate Task 9b regression proves panel Confirm opens lookup and survives pending/coalesced prefetch drain.
- Native auto-turn tests use an injected/wrapped clock: every rate maps to 60/20/10/5 seconds; overview skips directly to the next physical-page overview while panel mode follows panel navigation; Panels Only, zero-crop and end-of-book fallbacks are correct; busy work defers one turn without catch-up; `millis()` wrap works; Confirm, Back, touch-menu, lock, suspend and exit cancel; auto sleep is prevented only while active. A simulator log seam should distinguish manual and automatic moves.
- QR tests cover panel order, whole-page order, empty OCR, invalid metadata, multibyte UTF-8 at the 2,953-byte boundary, truncation, allocation failure and return-to-reader position. Render one maximum-size payload through the real QR encoder in a native test; stubs cannot validate capacity or failure handling.
- Screenshot tests assert it captures the restored manga frame rather than the popup, fills page/progress metadata, handles an SD write failure, and leaves the framebuffer unchanged after feedback. Run the configured global shortcut too, since it shares `getScreenshotInfo()`.
- Cache tests confirm cancellation and handle closure precede deletion, progress/bookmarks/stats survive, pixel/cover/scan derived files are removed, cancellation leaves the book open, and deletion failure is visible. Simulator navigation should confirm successful deletion returns Home and reopening regenerates rather than trusting partial cache data.
- Settings tests assert every displayed setting is actually consumed by manga, exclude generic status-bar and EPUB-only text/layout/indexing controls, and preserve page, panel, Panels Only and panel-rotation state on return.
- Plane-aware render tests assert overview `page/total`, panel `panel/count page/total`, and the translated Panels hint are present and in bounds for every orientation in BW, completed grayscale and deferred grayscale-upgrade paths. Seed nonzero masks and prove both status rectangles are cleared to zero in LSB/MSB while restored BW holds a white background and black glyphs. Simulator framebuffer hashes alone are insufficient; inspect pixels in each composed plane and after BW restoration.
- Shortcut tests dispatch both configured short-power word lookup and the Quick Actions/chord lookup enum through `ActivityManager`, asserting current panel/page OCR scope, modal/locked rejection and no duplicate action from a screenshot chord release.

## Hardware acceptance

On X4/C3 and Sticky or X4 Pro/S3, exercise every menu row from overview and a zoomed panel using physical buttons and touch where present. Let all four automatic rates turn at least twice, interrupt them during JPEG, PNG and BMP foreground work and prefetch, then test lock, sleep and resume. Verify QR with Japanese/multibyte OCR, screenshot filenames and pixels, and cache deletion followed by a cold reopen. Record free heap, largest allocation and prefetch task watermark during maximum QR and settings cycles; preserve user progress, bookmarks, stats, dictionaries and fonts.
