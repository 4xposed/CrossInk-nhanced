## Geometry, pixels and prefetch

`Matcha:MangaReaderActivity.cpp:591` computes full-page fit and aspect-triggered rotation; `:1049` computes panel fit with optional rotation. Worker and foreground share these pure geometry functions. Full-page geometry can be recovered from a cache header only if non-square, a fit fixed point, and touching a screen edge (`:654`); square/smaller cases probe source dimensions. Panel foreground uses remembered source crop dimensions; even an already-warm panel worker probes its source header (`:1260`).

Full pages use `<book cache>/page_<zero-based page>.2bp` (`:710`); crops use `p<page>_<panel>.2bp` (`:939`). `Matcha:lib/Epub/Epub/converters/PixelCache.h:23` defines only LE u16 width/height, then row-padded, MSB-first 2-bit pixels. There is **no cache version, source identity, source size/mtime/hash, or settings identity** in that header. Reader open checks header/positive dimensions (`PixelCache.cpp:45`), render accepts ±1 pixel dimensions and detects short body reads while drawing (`:78`). Source replacement with identical dimensions can therefore reuse stale pixels; cache-only existence checks also mistake corrupt files for already-warm assets. These caches are disposable and need not retain binary compatibility with converted manga.

One open cache handle is reused for all three planes; close it before source fallback rewrites the same cache (`MangaReaderActivity.cpp:783`). The upstream streaming writer limits bands to 24 KiB plus its spare row (`PixelCache.h:114`); cache reads allocate roughly 4 KiB then retry one row (`PixelCache.cpp:110`). These are bounded working buffers, not an extra framebuffer, but port with fallible owned allocations and validate dimensions before allocation/division. PixelCache's `abort()` is a member that removes a partial file (`PixelCache.h:226`), not libc process abort.

Monochrome BMP pages/panels use one BW fast refresh; grayscale page render uses BW and two cached planes (`:754–824`). Panel BW appears first and idle upgrades to grayscale after 400 ms (`:520,992`). Firmware must verify ghosting/plane behavior; the simulator cannot prove it. Preserve CrossInk's existing EPUB image/AA policy rather than wholesale replacing decoders.

Worker contract (`MangaReaderActivity.h:184`, `.cpp:1118`): one job/result slot, atomic busy handoff, generation validation, 150 ms first-panel / 400 ms next-page/panel dwell; 8192-byte worker stack and heap gates. Results apply on the loop with nonblocking RenderLock Try (`:1179`); worker should never touch the renderer in cache-only decode. Temporary cache output is published by rename, losing races drops temporary output (`:1231`). Exit signals cancellation and waits for worker before destruction (`:141`). **Cancellation is not always immediate:** JPEG callback ignores a cancellation request once cache writing is two-thirds complete (`Matcha:lib/Epub/Epub/converters/JpegToFramebufferConverter.cpp:148`), including exit-triggered requests. Therefore do not repeat the header's one-block shutdown guarantee without adjustment.

CrossInk `lib/Epub/Epub/converters/ImageToFramebufferDecoder.h:15` has no `cacheOnly`, callback, or cancellation context; `src/activities/RenderLock.h:6` has no Try/held interface. Its PixelCache header is a writer, not the upstream Reader API. Before enabling a worker, port/review cache-only JPEG and PNG paths, prove they do not initialize/read DirectPixelWriter/renderer state, and add coordination for same-source readers. Merely polling `RenderLock::peek()` does not establish exclusive storage/decode ownership. Source replacement, settings changes, temp publication, and cache cleaning need a shared invalidation/cancellation contract. Keeping foreground rendering first is a safe implementation sequence, but prefetch remains required for final parity.

## Dictionary integration preserving prior work

Upstream `MangaWordLookupActivity.cpp:20` flattens UTF-8 OCR into WordSelectionScan, first-word burst up to 1500 ms (`:56`), and 40 ms progressive loop scans (`:341`). Lookup is synchronous under RenderLock, with upstream grammar additions (`:142–296`). Left/right or configured side buttons advance words; other buttons scroll five definition lines; Confirm repeats lookup and Back/short power exits (`:298`). Fast refresh with periodic HALF_REFRESH every ten redraws (`:456`) matches the already accepted CrossInk cleanup policy. The audited activity contains no saved-word/clipping/history/nested-lookup UI contract; do not infer EPUB parity.

Reader combines panel OCR or all-page OCR with newlines (`MangaReaderActivity.cpp:1429`), restores Japanese SD fonts for the child and releases them for image decode afterward. It supplies `(u16 page, u16(panel+1))`, with zero representing overview, to a **single-slot** `wlscan.bin` cache. `Matcha:WordSelectionScan.cpp:354` (reader folder) hashes glyph content and fingerprints only main dictionary index size. Same-size replacement and other dictionary-file changes need stronger identity; that source cache is not an interoperability requirement.

CrossInk already provides `src/util/DictionaryEngine.h:30`, `src/activities/reader/PageWordScanner.h:29`, `PageWordScanCache.h:9`, `DictionaryDefinitionModel`, and `EpubReaderWordLookupActivity.h:25`. PageWordScanCache carries backend + glyph hash + u64 dictionary signature and validates candidate storage; retain it. Add an OCR text source adapter exposing `PageTextSourceView` (`PageTextSource.h:33`) with original text-block bounds and transformed screen coordinates, then use unified scanning/definition flow for both Japanese and StarDict. Existing direct-word activity constructor is for lookup of one text request; it alone does not deliver progressive OCR word selection. Preserve font miss/fallback fixes, cancellation/draining, nested lookup, history and saved-word behavior already in CrossInk. A bounded text/glyph cap must report truncation rather than persisting an incomplete scan as complete.
